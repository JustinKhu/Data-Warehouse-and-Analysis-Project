# Data Warehouse Project

## 📖 Overview
This project is an end-to-end **data warehouse build** that I created to strengthen my data analytics skills. 
The aim is to simulate a real-world data workflow — starting with **raw data ingestion**, then **cleaning and transformation**, and ending with a **star-schema model** ready for reporting and analysis.

Therefore, improving my knowledge and skills in data. This project will also be something I can work on in the future as I continue to accumulate more skills. 

---

## 🧭 Objectives
- Practicing designing and implementing a **data warehouse architecture** using SQL-based technologies.
- Import data from two sources (CRM and ERP) as CSV files. 
- Apply **ETL** to transform raw data into analytics-ready form.
- Clean and standardize raw data for easy analysis. 
- Combine both data sources into one data model to be used for analytical queries. 
- Provide clear and easy to understand documentation. 

---

## 🧱 Architecture
This project follows the **medallion architecture**:

| Layer | Description |
|-------|--------------|
| **Bronze (Raw)** | Stores ingested data in its original, unmodified state. |
| **Silver (Cleaned)** | Cleanses, standardizes, and transforms data for consistency. |
| **Gold (Analytics)** | Optimized for reporting and business intelligence queries. |
---

## Key Learnings 
- The importance of visually mapping out which keys connect to each other (especially when working with multiple tables).
- Best practice of conducting regular quality checks.
- Cleaning data efficiently by working in separate queries.
- The flow of data before it is analysed by a data analyst for business insights.
- The importance of standardized/compatible data from CSV files for efficient and seamless integration into SQL.
- Examining and deriving new columns to create compatible keys.
